# مخططات ورسومات المشروع

تم إضافة ملفات ERD وWireframes إلى مجلد docs/ في المستودع. المحتويات:

- docs/erd.svg — مخطط ERD بصيغة SVG (نظرة عامة على الجداول الأساسية والعلاقات). يحتوي على الجداول التالية: users, companies, chart_of_accounts, customers, vendors, products, tax_rates, invoices, invoice_items, payments, bank_accounts, journal_entries, journal_lines, audit_logs, import_jobs.

- docs/wireframes.svg — مخططات شاشات مبدئية بالعربية والإنجليزية: شاشة تسجيل الدخول، لوحة القيادة، قائمة الفواتير، شاشة إنشاء فاتورة، قائمة العملاء.

ماذا فعلت الآن:
- أنشأت ERD مبدئي وwireframes مرئية ومخزنة في المستودع (docs/).
- أضفت ملف توضيحي يصف محتوى الملفات وما يمكن توقعه لاحقًا.

الخطوات القادمة (أقترح تنفيذها بالتسلسل):
1. اعتماد المخططات: راجع ERD والwireframes وأخبرني بأي تعديل (حقول إضافية، تسميات بالعربي/انجليزي مختلفة، علاقات جديدة بين الجداول).
2. سأجهز specification تفصيلي نهائي (نموذج API مع JSON لكل endpoint) وأرفعه كـ docs/api_spec.md.
3. بعد اعتماد الـspec، أبدأ scaffold المشروع (FastAPI + React) وأدفع هيكل المشروع وdocker-compose مع إعدادات البيئة.
4. أنشئ قاعدة بيانات مبدئية مع بيانات عيّنة (sample data) وأعرض نتائج تقارير مبسطة.
5. أصمم قالب فاتورة PDF (عربي/إنجليزي) كقالب HTML/CSS جاهز للتحويل إلى PDF.

أسئلة مخصصة للاعتماد:
- هل تود تغيير أسماء الحقول الأساسية أو إضافة حقل مهم الآن (مثلاً: رقم ضريبي للعميل، فئة المنتج، مركز تكلفة...)؟
- بالنسبة لرقم الفاتورة، هل تنسقها بهذا الشكل: INV-{YYYY}-{0001} لكل شركة؟
- هل تريد أن أدرج مثال على بيانات عيّنة (مثال: شركة "شركة الألف"، عميل "علي"، فاتورة مبيعات بقيمة ...) أم أترك البيانات التوضيحية عامة؟

ردك على هذه الأسئلة يوجهني لصياغة مواصفات API التفصيلية وبدء scaffold المشروع.
